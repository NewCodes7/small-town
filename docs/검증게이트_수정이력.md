# 검증 게이트(verify-gate) 수정 이력

verify-gate 훅(에이전트 리뷰·컴파일·Spotless·SAST·테스트)이 잡아낸 문제와 수정 내용을 기록한다. 최신 항목이 위로.

---

## 2026-06-27 — 크롤링 에러 관리자 알림 기능

- **기능**: 크롤링 run 실패 시 관리자 전용 알림 생성 (`CrawlingRunService.finishRun` → `AdminNotificationService.notifyCrawlingFailure`)
- **검출**: 에이전트 리뷰(로직) [high]
- **문제**: `notifyCrawlingFailure()`가 기본 전파(`REQUIRED`)라 `finishRun()`의 트랜잭션에 합류. 알림 저장 중 `RuntimeException` 발생 시 공유 트랜잭션이 rollback-only로 마킹되고, `finishRun`의 `catch(Exception)`가 예외를 삼켜도 커밋 시점에 `UnexpectedRollbackException`이 발생 → 크롤링 실행 기록(`run` 상태/errorMessage) 자체가 롤백됨.
- **수정**: `notifyCrawlingFailure()`에 `@Transactional(propagation = Propagation.REQUIRES_NEW)` 지정해 독립 트랜잭션으로 분리. 알림 저장 실패가 자기 트랜잭션만 롤백하고 바깥 `run` 갱신은 정상 커밋되도록 함.
- **이유**: 부가 기능(알림)의 실패가 핵심 데이터(크롤링 실행 기록) 영속화를 깨뜨리면 안 됨. try/catch만으로는 rollback-only 마킹을 되돌릴 수 없으므로 트랜잭션 경계 분리가 필요.
